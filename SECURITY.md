# Security Notes for inspire

- **Supported variants**: InsPIRe^0 (NoPacking), InsPIRe^1 (OnePacking), InsPIRe^2 (Seeded+Packed). These are the only production-supported modes.
- **Modulus-switched responses**: the `mod-switch-response` feature is default-off in this crate and enabled by the adapter and client workspaces, which mod-switch every served response to `MOD_SWITCH_TARGET_36BIT` (`2^36 - 2^20 + 1`) and serialize it through the response serializer at 36 bits per coefficient, 10,446 bytes for a 512-byte row. The noise gate charges the target's residue `q' mod p` to the modelled error, and the constant is chosen for its residue of 33: the gate's ratio alone is identical for two primes of one bit width, and a seeded KAT (`production_post_switch_error_kat_at_45_36_and_33_bits`) pins error 652 at this prime against 53,503 at the largest 36-bit NTT prime (residue 53,266). The decode margin is measured on the switched response after the serializer by `served_post_switch_noise_distribution` (`benches/packing_noise_measurement.rs`, run with `--release --features mod-switch-response -- --ignored`), 1,000 samples per width across 40 sessions: worst error 1,113 against a decode boundary of 524,272 at 512-byte rows (gamma = 256), 8.88 bits of margin, and 417 at 32-byte rows (gamma = 16), 10.30 bits. It is taken across sessions because a session's packing key puts a fixed offset on every response of that session, so a margin taken inside one session reads a few tenths of a bit high. The modulus arrives off the wire, and `extract_inspiring_mod_switched` refuses, before deriving anything from it, any response modulus that is neither the CRS's own limbs nor an implemented target (45-bit, 36-bit). The checked 45-bit target passes the gate and the byte-identity corpus and is not served; the byte-aligned RIMS codec is not on the wire.
- **Rejected target**: The exported 33-bit target fails the conservative production-cell noise gate at 0.833x. Do not wire or enable it.
- **Packed a-side caveat**: At d=256, gamma=4, bounded dense and structured recovery attempts against independently generated actual responses failed. Failure is not a privacy proof; production d=2048 and cross-key security bounds remain unmeasured.
- **Reporting issues**: Please open a GitHub issue in this repository with a minimal reproduction or description. Avoid including sensitive data in issue text.
